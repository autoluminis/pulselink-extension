通知插件开发与发布

了解开放 SDK 的接入契约，以及企业私有交付和公开目录发布流程。

SDK 接入快速开始运行时与回执私有交付与信任验收与排错对外发布

SDK 接入

开发包版本 26.10.17.001，面向同版本宿主，包含公共通知契约源码、可独立构建的 Webhook 示例和接入说明。

下载通知插件开发包SHA-256 校验值
dotnet build src/PulseLink.Plugin.Abstractions.csproj -c Release
dotnet build examples/GenericWebhook.csproj -c Release

需要 .NET 10 SDK。此 ZIP 是开发源码包，不可作为通知插件安装包上传。部署插件时由宿主提供 SDK 契约程序集，无需复制 SDK DLL。

开发包不包含完整发行打包工具。正式安装包仍需通过授权发行工具链签名；编译示例不代表完成安装或兼容性验证。

开发环境使用 .NET 10，并引用与目标宿主版本匹配的 PulseLink.Plugin.Abstractions SDK 程序集。通知插件在宿主进程中运行，由管理员认可后安装。

下载完整开发指导书（Markdown） · 指导书、清单模板和独立回归程序也包含在 SDK ZIP 内。

插件入口与通知通道

  • INotificationChannelPlugin：插件入口，提供无参构造器，通过 CreateChannels() 返回一个或多个通知通道。
  • INotificationChannel：声明渠道 Key、显示名称、广播模式、联系人类型与默认配置。
  • ValidateConfigurationAsync：校验管理员保存的通道实例配置。
  • SendAsync：发送平台已完成策略匹配、模板渲染与收件人筛选的通知。

发送结果与运行约定

遵守取消和超时要求，准确区分服务方受理与实际送达。平台会记录投递并重试失败任务，外部发送与本地结果保存不构成原子事务；接收端应按 DeliveryId 处理重复投递。

需要后台服务、健康检查、操作日志或异步回执时，使用插件运行时契约。插件不能取得宿主数据库连接或其他模块内部服务。

快速开始：构建与调试

  1. 下载 ZIP 和 SHA-256 文件，使用下列 PowerShell 命令校验，再解压并进入 PulseLink-Notification-SDK。
  2. 运行构建与独立回归程序；测试使用内存 HTTP 替身，无需服务端或测试框架。
  3. 复制 examples，修改入口 Id、Version、命名空间以及项目 AssemblyName，并同步 plugin.json 的 pluginId、version、entryAssembly 和 entryType。
  4. 替换 marketplace.json 中的发行方、许可证、项目、帮助、支持和隐私地址。example.invalid 是占位地址，不能用于正式发布。
$zip = 'PulseLink-Notification-SDK-26.10.17.001.zip'
$expected = (Get-Content "$zip.sha256").Split(' ')[0]
if ((Get-FileHash $zip -Algorithm SHA256).Hash -ne $expected) { throw 'SDK 校验失败' }
Expand-Archive $zip -DestinationPath ./notification-sdk
Set-Location ./notification-sdk/PulseLink-Notification-SDK
dotnet build examples/GenericWebhook.csproj -c Release
dotnet run --project tests/GenericWebhook.Tests.csproj -c Release

Webhook 配置与发送

{"url":"https://your-server.example/pulselink/webhook"}

示例为广播通道，不需要联系人。配置校验和发送前均验证绝对 HTTP(S) 地址，拒绝 URL 账号密码与片段。公网使用 HTTPS；HTTP 只用于受控调试。

POST JSON 包含 deliveryId、eventType、severity、subject、body、attributes；Idempotency-Key 请求头使用同一 DeliveryId，不发送完整配置。每次发送最多 10 秒，传递取消令牌、不跟随重定向；HTTP 失败抛出交给宿主记录重试。接收端必须持久化去重，取消或超时不保证远端未受理。

插件实例持有并释放 HttpClient；停止后不再发送。项目引用设置 Private=false、ExcludeAssets=runtime，安装包不附带宿主提供的 PulseLink.Plugin.Abstractions.dll。

运行时、健康与异步回执

  • 后台连接：实现 INotificationPluginRuntimeAware，在 StartAsync 获取受限 runtime，在 StopAsync 取消并等待后台任务，释放连接和定时器。
  • 配置变化：INotificationPluginConfigurationAware；持续健康上报标记：INotificationPluginHealthReporter（有状态插件通过 runtime.ReportHealthAsync 上报，频率须高于宿主过期频率）；自定义管理操作白名单：INotificationPluginOperations。
  • 宿主能力：ListChannelConfigurationsAsync、GetPluginConfigurationAsync、UpdatePluginConfigurationAsync、SendHttpAsync、WriteLogAsync 和 ReportHealthAsync。只访问当前插件的数据，日志须脱敏。
  • 异步送达：用 ReportReceiptAsync 上报 NotificationDeliveryReceipt，关联原 DeliveryId 和提供方消息 ID。只有服务方确认真实送达时才使用 Delivered；HTTP 2xx 在示例中只返回 Accepted。

企业私有交付与信任

  1. 实现插件、维护 plugin.json 和 marketplace.json，构建时复制所需依赖与可选 UI 资源。
  2. 使用发布工具和自己的签名密钥生成插件 ZIP；向管理员交付签名包、密钥编号与公钥，私钥由开发者保管。
  3. 管理员进入“系统管理 → 插件信任”，核对公钥指纹并添加通知插件的安装授权范围。
  4. 在通知中心安装并启用插件，创建通道实例、配置联系人，再关联通知策略。

签名打包输入与命令

SDK 中 examples/plugin.json 是未签名输入，空 sha256 由发行工具填写；marketplace.json 是项目发布资料，不进入运行时 ZIP。SDK 不包含完整 ReleasePackager，取得授权工具后替换下列路径和自己的密钥编号执行：

dotnet run --project path/to/PulseLink.ReleasePackager -- plugin-pack `
  --project path/to/GenericWebhook.csproj `
  --private-key D:/plugin-signing/private.pem `
  --signing-key-id your-publisher-key `
  --allow-external-signing-key `
  --output artifacts/your-plugins

入口 ID、版本、程序集、清单必须一致。修改签名后的 DLL 或文件须重新打包；私钥保留在包外。

离线安装与商城在线安装分别授权；第三方公钥的导入、信任与授权是不同操作。版本回滚和新安装仍需满足当前信任要求。

私有插件可以只在企业内部交付，无需公开到官方仓库。部署前验证成功、失败、超时、取消、重复发送与配置兼容性。

向其他用户公开发布

  1. 使用稳定插件 ID 和递增的三段版本，保持程序集、运行时清单与发布描述一致。
  2. 在 marketplace.json 维护发行方、开发者、公开可访问的说明、支持方式、许可证与适用的隐私资料。
  3. 生成签名 ZIP 及发布描述，声明最低宿主版本、可选兼容上界和本次变更说明。
  4. 按目标目录的发行方与发布密钥要求提交材料。官方目录需要相应审核与授权，第三方发行身份不会自动变成官方身份。

本仓库的插件发行 PR 使用 publish/notification-{pluginId}-{version} 分支，仅将同一插件同一版本的 ZIP 与 release.json 放入 incoming/。官网维护 PR 使用独立分支，不走插件入库流程。

安装验收与故障排查

  1. 核对宿主版本、发布公钥指纹和安装授权，在通知中心上传签名插件 ZIP 并启用。
  2. 创建通道实例并配置真实接收端，将渠道关联通知策略，产生真实事件并核对两端 DeliveryId。
  3. 验证成功、配置错误、HTTP 失败、超时、发送中取消和重复投递；验证插件停用、宿主重启、旧配置升级及版本回滚。
  4. 分别保存编译回归、宿主安装、真实服务发送和异步回执证据，记录宿主/插件版本、场景与实际结果。

常见问题

  • 无法加载：核对 entryAssembly、entryType、public 无参入口、依赖和目标宿主契约版本。
  • 摘要或签名失败：检查签名后是否修改包内容、公钥是否匹配、安装授权范围是否正确。
  • 受理后未送达：查看提供方结果和回执，不把 Accepted 当作 Delivered。
  • 重复消息：接收端按 DeliveryId 持久化去重；发送和宿主结果保存不是原子事务。
  • 升级失败：检查旧渠道 Key 和已有配置是否兼容，查看宿主恢复旧版本的原因。
