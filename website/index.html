02 / CONNECT

连接不同设备，读懂同一份数据。

已有 OPC UA 服务器直接连接。其他协议通过内置网关，进入统一监控链路。

OPC UA 客户端

从节点浏览，到持续订阅。

管理外部 OPC UA 连接，将节点绑定到业务设备与点位，持续获取数值、质量与时间戳。

  • 节点浏览、读取与订阅
  • 证书审批与连接诊断
  • 连接重连与订阅恢复
  • 按权限写入与方法调用
内置协议网关

统一点位，保留设备差异。

内置 Modbus TCP、Siemens S7、MQTT 驱动，将源点位映射为内部 OPC UA 变量。

  • 数据源与点位映射管理
  • 稳定 NodeId 与源时间
  • 质量与失鲜状态诊断
  • 接入实时、历史与规则

采集与映射数据源 → 源点位 → 节点
内部 OPC UA 节点值、质量与时间戳
设备监控与告警实时 / 历史 / 规则 / 通知

内置网关为本机只读浏览、读取与订阅路径；外部 OPC UA 客户端的写入能力单独按权限管理。部署前需确认现场设备与协议兼容性。

03 / NOTIFY

异常发生，让消息找到负责人。

消息通道、接收人与通知策略分别配置，结合值班安排和分阶段升级跟进告警。

消息渠道扩展

消息与协作

通过通知插件接入消息平台、邮件或协作工具，将设备告警融入团队日常处理流程。

服务与设备对接

短信与语音

通过插件对接短信服务、语音网关或专用通知设备，覆盖需要手机和电话提醒的场景。

开放 SDK

企业私有通知

使用 .NET 通知插件 SDK 对接内部消息系统、自建服务与业务接口，自主定义通知方式。

统一策略，触达该处理的人。

按设备、级别与事件选择接收人和通道，结合工作窗口、值班安排与分阶段升级持续跟进；复用模板、投递记录及失败重试。

内部私用，或作为独立插件发布。

基于开放 SDK 开发、签名和打包。可在企业内部受控部署，也可按发行规范提交公开目录，向其他 PulseLink 用户交付。

上述为可扩展的通知类型，并非全部内置。具体可用方式以已发布并启用的插件为准；服务账号、接口与硬件要求由对应插件说明。

04 / RULES

定义异常，让通知有据可依。

设备规则判断“是否异常”，通知策略决定“通知谁、用什么通道、是否升级”。

规则定义

让条件明确，
让状态变化可追溯。

组合判断

数值、布尔、字符串比较；最多 16 条条件，支持 AND / OR。

稳定性控制

触发与恢复防抖、恢复滞回、连续匹配次数。

数据时效

变化率与无数据超时，覆盖波动和停止更新的状态。

企业内部私有部署

  1. 对接企业内部服务、接口或通知设备。
  2. 使用自己的签名密钥打包，交付插件 ZIP 与公钥。
  3. 管理员在“系统管理 → 插件信任”核对公钥并授权对应安装范围。
  4. 在通知中心安装、启用插件，创建通道实例并关联策略。

私有插件无需在官方仓库公开，内部服务地址、凭据和私钥不应作为公开发布资料。

对外公开发布

  1. 维护 plugin.json、marketplace.json 及使用说明。
  2. 声明版本、兼容范围、维护者和适用的隐私资料，生成签名 ZIP 与发布描述。
  3. 按目标目录的发行方与发布密钥要求提交发布材料；官方目录需经过相应审核与授权。
  4. 发布成功后由目录供用户发现和安装，持续维护兼容性与版本说明。

第三方发行身份与官方身份分别管理，公开仓库中的任意 ZIP 不会自动成为官方插件。
