通知插件开发与发布

了解开放 SDK 的接入契约，以及企业私有交付和公开目录发布流程。

SDK 接入私有交付与信任对外发布

SDK 接入

开发环境使用 .NET 10，并引用与目标宿主版本匹配的 PulseLink.Plugin.Abstractions SDK 程序集。通知插件在宿主进程中运行，由管理员认可后安装。

插件入口与通知通道

  • INotificationChannelPlugin：插件入口，提供无参构造器，通过 CreateChannels() 返回一个或多个通知通道。
  • INotificationChannel：声明渠道 Key、显示名称、广播模式、联系人类型与默认配置。
  • ValidateConfigurationAsync：校验管理员保存的通道实例配置。
  • SendAsync：发送平台已完成策略匹配、模板渲染与收件人筛选的通知。

发送结果与运行约定

遵守取消和超时要求，准确区分服务方受理与实际送达。平台会记录投递并重试失败任务，外部发送与本地结果保存不构成原子事务；接收端应按 DeliveryId 处理重复投递。

需要后台服务、健康检查、操作日志或异步回执时，使用插件运行时契约。插件不能取得宿主数据库连接或其他模块内部服务。

企业私有交付与信任

  1. 实现插件、维护 plugin.json 和 marketplace.json，构建时复制所需依赖与可选 UI 资源。
  2. 使用发布工具和自己的签名密钥生成插件 ZIP；向管理员交付签名包、密钥编号与公钥，私钥由开发者保管。
  3. 管理员进入“系统管理 → 插件信任”，核对公钥指纹并添加通知插件的安装授权范围。
  4. 在通知中心安装并启用插件，创建通道实例、配置联系人，再关联通知策略。

离线安装与商城在线安装分别授权；第三方公钥的导入、信任与授权是不同操作。版本回滚和新安装仍需满足当前信任要求。

私有插件可以只在企业内部交付，无需公开到官方仓库。部署前验证成功、失败、超时、取消、重复发送与配置兼容性。

向其他用户公开发布

  1. 使用稳定插件 ID 和递增的三段版本，保持程序集、运行时清单与发布描述一致。
  2. 在 marketplace.json 维护发行方、开发者、公开可访问的说明、支持方式、许可证与适用的隐私资料。
  3. 生成签名 ZIP 及发布描述，声明最低宿主版本、可选兼容上界和本次变更说明。
  4. 按目标目录的发行方与发布密钥要求提交材料。官方目录需要相应审核与授权，第三方发行身份不会自动变成官方身份。

本仓库的插件发行 PR 使用 publish/notification-{pluginId}-{version} 分支，仅将同一插件同一版本的 ZIP 与 release.json 放入 incoming/。官网维护 PR 使用独立分支，不走插件入库流程。
